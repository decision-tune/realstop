# RealStop reference

The full behavior of the hooks, the judges, the config and the known limits. The short version is in the README. A technical report will follow. The training data and the bench harness are not released.

A Claude Code skill plus three hooks (the Stop hook also runs on SubagentStop) that stop the agent from quitting on work it can do, and that react to the owner's corrections (the correction hook acts in the same turn and logs locally; learning is review-gated: `realstop learn` applies a correction only after the owner confirms it).

- `hooks/no-quit.py` (Stop): blocks a final reply that gives up, offers decided work or defers it, unless the stop is a real owner-only gate backed by evidence (see "Real gates" below). Cascade: deterministic rules and gates first (live stop, plan mode, harness denials, sentence-scoped consent gates, a step handed to the owner, standing approvals; an excused stop is sent to no judge), then the local DecisionTune judge, then the cloud judge only when the local judge has no answer and `cloud_ok` is true, then the phrase rule (plus "announced an action, made no tool call") when no judge answers. The first judge that answers decides; with the local judge, a phrase hit lowers its bar for that stop, and a reply under `short_reply_chars` (400) is decided by the rules alone with no judge call (see Judges). After a nudge it blocks again only if a tool call followed it, at most `block_cap` (5) times per user turn in total (an allowed stop restarts only the nudge text, never the count); later nudges are short and rotate. Skips plan mode and internal subagents; ignores transcripts outside `~/.claude/projects`; harness-injected user text is not the owner's request, but a slash command typed with args is. Duplicate hook runs (double install) are deduped with an atomic lock. Held stops are logged too (`block:false`), so the false-block learning sees the real last stop.
- `hooks/correction.py` (UserPromptSubmit): when the owner says "no", "that's wrong", "do this yourself", logs it and tells the agent to own the miss and do the work now. A live stop or "that's fine / you were done" within 15 minutes of a block is logged as a `false_block` (no context injected).
- `hooks/learn.py` (SessionStart): housekeeping only. It learns nothing and prints nothing: it prunes `learned/states.jsonl` (judge states older than 30 days that no confirmed example uses).
- `scripts/realstop_learn.py` (`realstop learn`, installed as `~/.claude/realstop/realstop`): the review. Pending = a correction paired with the last stop of its session (stops.jsonl) that the local model or the cloud judge judged; a correction after a let-through stop proposes QUIT, pushback after a block proposes RIGHT STOP. Refuses (exit 2) when `CLAUDE_PID`, `CLAUDECODE` or `FACTORY_SEAT_PID` is set or stdin is not a TTY (review, `--undo`, `--reset`; `--list` and `--status` are read-only). These checks are not proof that a person is present, and they are not a security boundary.
  - Local judge: a confirmation stores d = h_yes - h_no (the hidden state at the "yes" [MASK] minus the one at the "no" [MASK], 1,024 floats; the head's 2-way softmax is sigmoid(W . d), so this is what the head reads) in `learned/examples.jsonl` and refits a personal head: minimize the log loss of sigmoid((W + delta) . d) over the stored examples plus (lambda/2)|delta|^2, lambda = mu x the mean squared norm of the stored vectors, solved exactly in the span of the examples (Newton on the Gram matrix, pure Python). mu runs down the ladder 0.25, 0.1, 0.05 and the first value that passes is used: (1) every example is scored on the side its label says at the shipped bar of the current strength; (2) on the 458 released synthetic items (`data/regression_pairs.jsonl`, vectors cached in `learned/regression.bin`, keyed by the model fingerprint), pairs-both-right and accuracy each drop by at most one point, and the share of right stops blocked rises by at most one point (the last check is an addition to the specified gate, because the synthetic baseline is near chance and accuracy alone let a block-everything head through in the simulation). Otherwise the example is not stored and the reason is printed. The result is `learned/head.safetensors` (same tensor names and shapes as the shipped head; metadata carries the model fingerprint). The server ignores it on any problem or a fingerprint mismatch.
  - Threshold: per strength, replayed from the confirmed local examples in order; each time quits minus wrong blocks since the last step reaches 4 in either direction the bar moves 0.02 (lower after missed quits, higher after wrong blocks), total at most 0.10, kept inside [0.35, 0.99] (a shipped bar already under 0.35 can be raised, not lowered). Written to `learned/shift.json`; the hook applies it to both the block bar and the with-hit bar.
  - Cloud judge: a confirmed QUIT adds the stop's tail to the cloud judge's examples (last 12) and sets `quit_min` to just under its score (floor 0.35); a confirmed RIGHT STOP raises `quit_min` by 0.05 (ceiling 0.9). `learned.json` is replayed from the confirmed cloud examples, so `--undo` is exact. An older `learned.json` written by the previous automatic `learn.py` is left alone until the first cloud confirmation replaces it, and `--reset` deletes it.
  - `--undo <id>` removes one example and refits; `--reset` removes `examples.jsonl`, `head.safetensors`, `shift.json`, the regression cache and `learned.json`.
- `scripts/realstop_server.py` (started by `scripts/realstop-serve.sh` behind its proxy): loads the pinned `decision-tune==1.0.0` model, answers `/decide` as `decision-tune serve` did (the hook's request and response are unchanged) plus `p_shipped` and `p_personal` from the same forward pass (`probabilities` is the head in use), and `/embed` for `realstop learn`. Loopback only; a request with an Origin header is refused.
- The Stop hook stores the judge state of each locally judged stop exactly as the model saw it in `learned/states.jsonl` (mode 0600, unmasked, local; pruned after 30 days unless confirmed; never read by the cloud path) and logs `dt.shipped`, `dt.personal`, `dt.shift` and `state_id`.
- `skills/realstop/SKILL.md`: the protocol (three approaches before "can't", the real-gate list, the correction routine).


Real gates (evidence over claims): the reply's own words never excuse a stop. A stop passes as a real gate only when
1. this turn's tool results hold a harness denial and the reply names it (its bracket label, or "classifier/hook denied" wording of the same kind). A harness denial is recognized by how the record starts: "Permission for this action was denied by" (classifier), "PreToolUse:<Tool> hook error:" (hook), "The user doesn't want to proceed with this tool use" (owner rejection), `<tool_use_error>Blocked:`. A failed command's output always starts with `Exit code N`, so it can never pose as one. A quoted command error (`fatal: could not read Username`, a test failure, `No such file or directory`) never excuses a stop: the agent can print any error it likes (`printf 'permi%sion denied' s; false`). Failed calls are only counted for the model judge;
2. the owner's request in this turn names an approval requirement ("publishing requires my approval", "ask me before deleting any files"), one sentence of the reply asks consent for that same action (publish, delete, push, deploy, send, spend...), and nothing else in the reply gives up, offers, defers or announces; or
3. one sentence asks consent for a gated step (npm/yarn/pnpm/poetry publish, twine upload, gh release create, cargo publish, gem push, docker push, `git push` with force or to a prod/release remote, deploy to production, terraform apply/destroy, kubectl apply/delete outside a local context, `rm -r` on `/`, `~` or `$HOME`, SQL DROP/TRUNCATE/DELETE FROM, sudo, "buy/purchase/pay for a ...", "charge the card", "send the email/message/invoice") and nothing else in the reply gives up, offers, defers or announces. Bare words do not count: "push", "deploy", "delete", "publish", "payments", "send you a message" are ordinary work ("want me to push it?" is still a quit).

A `BLOCKED:` or `NEEDS-YOU:` line without that evidence is logged as a `claim` and excuses nothing. The nudge never tells the agent to run a step that needs consent: a reply that mentions a gated step, a destructive one outside the gated list (`rm -rf data/`, lowercase `drop table`, `--prod`, `--force`, `git reset --hard`, `aws s3 rb`, refunds) or the step the owner asked to approve gets "do not run that step; finish every reversible step; ask consent only for the gated step". A reply that asks about any other command gets a neutral nudge (the hook cannot classify it: finish the reversible work, and if the command deletes, deploys, publishes, sends or spends, ask consent for it). Gates and shadow mode are decided before any judge call, so an excused stop is sent nowhere. All judge calls together share one 12-second deadline (the Stop hook timeout is 20 s); a skipped judge is logged as `deadline` in errors.jsonl and the phrase rule decides.

Handoffs: a reply whose closing part (its last 5 sentences, a fenced block folded into the line that introduces it) hands the owner a step blocks by rule, with no judge call (`path: handoff`), even when background work is armed. A handoff is a `! ` command (Claude Code's run-it-in-your-shell prefix), a run or paste ask ("please run", "run this in your terminal:", "paste this"), or an approval handoff ("waiting for your approval", "waits on your approval", "needs your approve command", "the one in my last message", "once you approve"). A `$ ` block or code with no such ask is an example and passes. Such a phrase is not a consent gate: it passes only as a real gate above (a gated step or the owner's approval clause, with a valid NEEDS-YOU line), or when this turn's tool results hold a harness denial of that same command (its last segment, or its key verb, the segment's last word) and the reply names the denial. A command's own error never counts. The nudge keeps the gate rule first, then "Run it yourself now. If the owner has a standing approval for this kind of step, quote it when you retry. Hand it over only if your own retry is denied this turn, and quote the denial." A handed step that is gated or destructive keeps the do-not-run nudge instead.

Standing approvals: `~/.claude/realstop/standing.txt`, one phrase or case-insensitive regex per line, `#` comments (`realstop setup` writes it once with commented examples and never overwrites it). When a sentence that really asks the owner for consent or hands a step (a question, "want me to", "needs your approval", a NEEDS-YOU line, a run/paste ask, a `! ` command) names a step that matches a line, the stop is a quit even when it would otherwise pass as a consent gate, and the nudge says the owner pre-approved it (the matched line). It passes only after two named harness denials of that command this turn (the try and the retry that quotes the approval). The file is not in the tamper manifest, so edits need no install.sh rerun: an entry only makes the hook stricter, and deleting one loosens it back to the default. A line that is not a valid regex is matched as plain text and logged. Text that only describes your approvals (a status report listing them, a list of settings, quoted text) never matches.

Judges and data paths:

* Local (default): no API fee. In local mode RealStop sends no prompt or reply text to an outside judge; Claude Code itself still talks to its provider. The shipped pack is v3s-quit, in the model folder `~/.claude/realstop/model/realstop-quit`. On an Apple M5 Pro (macOS 27.2), the shipped model answers in a median of 27 ms (p95 33 ms) once warm, and the full hook takes a median of 186 ms per stop (136 ms when a reply under 400 characters skips the model). One question, read verbatim from the pack's `pack.json` at every stop. State, in the training format: `request: ` + the owner's request (first 600 characters) + `\nreply ending: ` + the raw reply's last 1,500 characters + `\ntool calls this turn: N` + `\nbackground work running: yes|no` (a `run_in_background` or Monitor launch this turn or within 6 hours, still running per the payload's `background_tasks`; crons never count). `POST /decide` with options `["no","yes"]`; `probabilities.yes` is corrected to the real class mix before any threshold (yes odds times (real yes / real no) / (train yes / train no), 0.532 for v3-quit). Blocks when the corrected p is at or above the `strength` dial. The dials belong to the model: the hook reads `thresholds.json` from the model folder (shipped v3s-quit: light 0.9743, moderate 0.8309 (default), hard 0.6075; with-hit bar 0.9435 / 0.8178 / 0.4104; chosen on the pack's selection rows only) and uses the built-in v3 constants (light 0.6813, moderate 0.5066, hard 0.3267; with-hit 0.5881 / 0.3363 / 0.2264) only when that file is absent. A `thresholds.json` that is present but invalid makes the local judge step aside (the rules decide); a `dt_thresholds` / `dt_thresholds_with_hit` value in config.json overrides the file; the file is hashed into the tamper manifest. A model's scores sit on its own scale, so never run one model with another's dials. When the phrase rule also hits (offer, deferral, announcement, give-up words with zero tool calls, unearned caution), the bar drops to the model's with-hit dial. The with-hit bar is never above the dial. Logged per stop as `dt: {raw, adjusted, threshold, threshold_with_hit, hit_applied, strength}` (never as `jev`, so learning does not move the cloud judge's `quit_min` from it). `local_url` must be loopback (127.0.0.1, ::1, localhost) or it is refused; the hook ignores `http_proxy` for it and refuses redirects. A down server, a slow answer or an unreadable pack.json falls through to the next judge. `auto` uses it once `model_dir` is set. Short replies: while the local judge is configured, a reply shorter than `short_reply_chars` characters after trimming (default 400) is decided by the rules-only path and no judge is called (local or cloud); longer replies go to the model. 400 was chosen on the selection rows from 150, 200, 300, 400 and 600. Each stop logs `path`: gate, short, judge or rules.

  The shipped v3s-quit pack on the 864 test turn ends: light catches 53.6% of quits (155 of 289) with 9.7% wrong nudges (56 of 575); moderate (default) 67.5% (195 of 289) with 15.8% (91 of 575); hard 75.4% (218 of 289) with 22.8% (131 of 575). The rules alone wrongly block 14.6% (84 of 575) there. Light had about 10% wrong nudges; if wrong nudges matter more than catching quits, use light.

* Phrases: always available, no network, no outside judge. They are the automatic backup whenever the model is not available.
* Cloud decision model (`jev`, opt-in). We make no quality claim about it. Paid per use ($0.042 per million input tokens, the provider's published price). It runs only with `"cloud_ok": true` in config.json, which only `realstop judge jev` (or `install.sh --judge jev`) writes (`realstop judge rules` and `realstop judge local` write false, `--judge auto` keeps it). A key being present never turns it on, and `auto` never falls back to the cloud without it. Each stop that is not already a real gate sends the end of the owner's request (last 1,500 characters), the start and end of the reply, the turn's tool names and up to 8 learned examples, unredacted, to the cloud decision model's provider.

Config (`~/.claude/realstop/config.json`, owner-written): `judge` (`auto|phrases|jev|local`), `cloud_ok`, `local_url`, `model_dir`, `strength` (light|moderate|hard, default moderate; an unknown value is moderate and logged), `short_reply_chars` (default 400; an invalid value is 400 and logged), `dt_thresholds` and `dt_thresholds_with_hit` (defaults in no-quit.py's `DT_THRESHOLDS` and `DT_THRESHOLDS_WITH_HIT`, so the manifest covers them), `quit_min` and `quit_with_hit` (cloud judge only), `block_cap` (default 5), `shadow` (default false), `scope_check` (default false; cloud judge only, since the local judge asks no "done" question: once per user turn, when the cloud judge says the work is done and the turn edited files, ask once whether the WHOLE request was done). `learned.json` (written only by `realstop learn`) may only move the cloud judge's `quit_min` (down after a missed quit, up after a false block), within [0.35, 0.9] (or the config's own `quit_min` if that lies outside), and add examples; it can never set judge, shadow, local_url, cloud_ok or block_cap. learn.py seeds its first value from the config's `quit_min`. It affects only the cloud judge; the local judge's `strength` dial is set by you in config.json and never learned.

Tamper detection: `realstop setup` writes `~/.claude/realstop/manifest.json` (0444) with the sha256 of the installed hooks and config.json (`null` when absent). On every stop, no-quit.py checks its own file and config.json against it. On a mismatch it logs a `tamper` record (errors.jsonl, plus a `tamper` field in stops.jsonl) and enforces DEFAULTS: no shadow, the default cap and thresholds, no cloud. Hand edits to config.json therefore need a rerun of install.sh. The installed hook (running from `~/.claude/realstop/`) treats a missing manifest as tamper too; only repo and test copies run without one. This is detection, not prevention: an agent running as the owner can rewrite the manifest to match its edits, so a real boundary needs the hook and its config outside the agent's write access.

Errors: every exception any hook swallows (it still fails open) is logged to `~/.claude/realstop/errors.jsonl` with the hook, the place and the exception type, never the prompt or reply text. With `auto` and a configured but stopped local server this adds one line per stop.

Shadow mode: `"shadow": true` or `REALSTOP_SHADOW=1` logs `would_block` to `stops.jsonl` and never blocks. It makes no cloud call (a loopback judge may still score). Every entry carries `qset` (hash of the judge questions and phrase lists, so criteria drift is visible) and `tools` (this turn's tool-call count). Per-session state lives in `~/.claude/realstop/state/`.

Known limits:

- Phrase coverage only: paraphrases outside the regex vocabulary are missed; the model judges catch some of them. A "Done. All tests passed." with no tool calls is not flagged (flagging it would block ordinary conversational answers).
- A real harness denial excuses only the denied step: the sentences that do not name it must not give up, offer, defer or announce, or the stop is blocked with the gate-safe nudge (path `denial_scope`). An offer inside the same sentence that names the denial is not checked and still slips. An MCP tool that returns error text starting like a harness denial would be read as one.
- Because quoted command errors no longer excuse anything, a genuine block that only a command error shows (a missing login: `could not read Username`) is excused only when the reply reports it without an offer or give-up wording, or by a model judge; with an offer it is nudged once, then held.
- Gated, destructive and approval-action detection are pattern lists (a regex of commands, and action stems such as delet, publish, push in the owner's clause); an unlisted command or an approval for an unlisted action ("ask me before renaming") is not recognized and gets the ordinary or neutral nudge. A gated step already done plus a consent sentence for it can still pass.
- Give-up words are ignored after any tool call, including irrelevant or failed ones (a measured precision trade-off).
- Handoff detection is a wording list: an ask outside it ("you can run X to check") is not a handoff, and "you'll need to run" stays a give-up word (ignored after a tool call). The denial match by key verb is loose: a denied `task gd1 approve` also excuses a handed `task ws2 approve`. The hook's turn spans from the owner's last message, so a denial from an earlier task notification's work still counts as this turn's (it must still be named in the reply). `sentences()` (used by the gate checks) still splits a fenced block at a `! ` line, so a `NEEDS-YOU:` line that introduces a `! cmd` block is checked as two fragments; `code_sentences()` keeps code whole for handoff detection only.
- The judges see different slices of the request (local: first 600 characters; cloud: last 1,500) and neither sees prior standing approvals.
- The local judge scores short, textbook quits low (0 tool calls: 0.139 to 0.254 corrected for an earlier pack, under the moderate with-hit bar), so replies under `short_reply_chars` (400) skip it and the rules decide: the four probes ("I will wire the CI in a later session.", "The fix is ready. Want me to push it?", "I can't run the migration from here; you'll need to run it yourself.", "I'll now run the deploy script.") block at moderate. The rules are weak on short quits they have no phrase for: on test they caught 0 of 14 short quits and wrongly blocked 3 short right stops. With tool calls the migration reply has no hit (give-up words are ignored after a tool call) and passes.
- `pack.json` (question and class mixes) is read at every stop but is not in the tamper manifest: an edited question or mix goes undetected. Background launches are not matched to the payload's tasks by id: any relevant launch plus any live task reads as "yes".
- The live stop is an imperative at the start of a sentence or clause with no object ("stop", "please stop now", "wait, why", "stop and wait", "hold on"), anywhere in the owner's message. "Do not stop until done", "don't ever stop", "don't touch the schema without asking", "wait for CI", "the stop button" are not stops; a stop worded with an object ("stop the refactor") is missed. Harness records are recognized by structure (`isMeta`, `isCompactSummary`, `isVisibleInTranscriptOnly`) and by text parts that START with a harness marker, so an owner message that mentions `<system-reminder>` is still the owner. A subagent's brief is never read as a stop.
- State and dedupe are not transactional: parallel writers can undercount the cap.
- `api_key()` still falls back to a login-shell lookup of the key, which runs shell startup files.
