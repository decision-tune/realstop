# Public system benchmark v1

This is a fresh synthetic evaluation, not evidence of production accuracy. Sixty fictional Cedar workspace cases use no private logs, existing 96-case labels, or model predictions. Fifteen families each have two unfinished and two legitimate stops across Claude and Codex transcript encodings. Artifact, test, and release-preparation families are development (12); all other families are holdout (48). The family split is fixed before calls.

Gold is recomputed from separate fixture worlds: required output files, actual fixture file inventory, owner stop, tool budget, available and denied tools, and launched jobs with resumable callbacks. Reply claims do not establish completion. The same reply appears on both sides of many pairs. Required output inventories are supplied by the fixture task harness. Files are simulated immutable artifacts, not results of running a real agent. Filenames and tool receipts provide evidence; no gold or feasibility Boolean is passed to judges. Labels, world checks, and expected live behavior are outside the packet.

Families cover completion claims, test receipts, release and production gates, shell failures and alternative tools, unstarted offers versus launched jobs, explicit owner stops, exhausted budgets, malicious document instructions, literal quoted requests, incomplete coverage, cached network alternatives, callbacks, scope limits, and harness denials. Missing coverage has a known world label but expected live behavior is fail-open. The production gate scenarios include unfinished independent preparation, so an approval request must not excuse that remaining work.

Limitations: these controlled pairs are correlated, fictional task inventories are simpler than real repositories, and tool receipts are simulated. Two platform encodings of a scenario are not independent observations. Report family-level results and individual failures; do not claim 60 independent production trials or novelty from synthetic breadth. Complete inventories do not test file-content semantic correctness. The native packet and compact candidate projection intentionally differ; their comparison measures the deployed systems, not a controlled model-only comparison.

## Freeze and run

Run `python3 scripts/system-benchmark.py validate`, then `freeze` before any model calls. The manifest freezes fixture inputs, labels, scorer code, documentation, and per-case representation hashes. Freeze refuses to overwrite differing material. Score refuses modified frozen files. An altered benchmark requires a new version. Model transport implementations, model identities, settings, and hook commit must additionally be recorded in the run record; the benchmark manifest does not freeze external transport code.

Each case contains `packet` with only sources `{source_id, role, text}` and coverage metadata. Pass `packet` and its canonical SHA256 separately to the native verifier. Never pass `world`, `gold`, or `expected_live_behavior`. `candidate_input` is the exact six-string projection: context, request, standing_approval, tools, tool_results, reply. Its canonical hash must match any reused candidate prediction. A reply-only or older 96-case prediction is incompatible.

Claude and Codex `transcript` and `hook_payload` are provided for replay adapters. Materialize the transcript in a fresh temporary directory and replace the payload transcript path for Claude. Legacy must mean the actual baseline hook at its recorded commit, with a clean isolated home and recorded configuration. Record tool/backend failures separately; never silently substitute a rule-only baseline for a configured baseline. Codex payload uses the actual command Stop hook contract (hook_event_name, session_id, transcript_path, turn_id, stop_hook_active, last_assistant_message). Replay it through the new adapter; record baseline support separately. No model calls are made by this script.

Compare four arms: actual legacy hook, candidate alone, native alone, and candidate-positive/native-confirmed cascade. Native nonconfirmation or invalid output abstains and allows the stop; deterministic live gates remain in the integration arm. Native-alone accuracy and live-gated behavior are distinct outputs. Use each case expected_live_behavior for integration assertions, including missing-coverage fail-open. The scorer reports classification accuracy, FP/FN, abstentions, fail-open operational FN, verifier calls, mean/p95 latency, and missing-case counts separately for development and holdout. No unlabeled or absent case is counted correct.

Predictions are JSONL with case_id, arm (`legacy`, `candidate`, `native`, `cascade`), input_hash, prediction (`QUIT`, `STOP`, `ABSTAIN`), latency_ms, verifier_calls. Cascade additionally requires candidate_hash. Native uses packet_hash; candidate uses candidate_hash; legacy uses hook_input_hash. Record cascade output after actual candidate gating, with zero verifier calls for candidate-negative cases. Preserve raw predictions and transport receipts alongside scores. Scoring rejects duplicates and representation mismatch. Run `score --predictions run.jsonl`.

Quota: root authorization controls all calls. The authorized ceiling is 53 against starting usage 43: at most ten further metered calls, counting failures/retries. Prefer one batch per arm if the provider supports it; do not assume batching makes calls free. Freeze before starting and report exact before/after quota receipts. This script cannot authorize or enforce provider quota.

Codex Stop fixtures contain authentic response_item records without fabricated Claude ancestry. Native packet coverage is the authored fixture observation; live adapter coverage is independently derived and may abstain more broadly. `workspace_inspect` is explicitly authorized as a simulated test harness in each owner request. Integration records may add live_disposition (block/allow), scored against expected_live_behavior separately from gold classification. Cascade call-count correctness must be verified by the runner against paired candidate outputs. Packet-identical platform repetitions should additionally be deduplicated by packet hash in analysis; primary counts remain replay counts, not independent samples.
