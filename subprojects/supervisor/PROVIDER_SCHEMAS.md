# Native hook capture schema v1

This is an experimental, uninstalled command-hook adapter. It accepts one JSON object on stdin and always outputs `{}` for valid CLI invocation, without modifying host decisions. Supply `--provider`, `--task`, `--session` and a private `--database`. The session filter must be explicitly configured. This process trusts that the local hook caller is the stated provider; it does not authenticate IPC or establish provenance cryptographically.

Sources: [Claude Code hooks reference](https://code.claude.com/docs/en/hooks) and [Codex hooks reference](https://learn.chatgpt.com/docs/hooks), checked 2026-11-05. Schemas and supported hook paths vary by host version; validate actual local host versions before installation. Codex hosted tools and some specialized paths do not emit tool hooks. Claude validation rejections and permission denials need separate handling. Capture is therefore not complete coverage.

| Hook | Claude | Codex | Ledger kind and identity |
| --- | --- | --- | --- |
| UserPromptSubmit | prompt, optional prompt_id UUID | prompt, turn_id | user; Claude prompt ID when present, otherwise generated ID and identity gap |
| PreToolUse | tool_use_id, tool_name, tool_input | same plus turn_id | tool_call; scoped tool ID |
| PostToolUse | tool_use_id, tool_name, tool_input, tool_response | same plus turn_id | tool_result; scoped tool ID |
| PostToolUseFailure | tool_use_id, tool_name, tool_input, error | unsupported here | tool_result; scoped tool ID |
| Stop | last_assistant_message | same plus turn_id | assistant; generated delivery ID, identity gap |
| SessionStart, SessionEnd, PreCompact, PostCompact | supported inputs | supported inputs | lifecycle; generated delivery ID, identity gap |

Tool IDs are scoped by provider and session and phase. An identical replay is idempotent; different content for the same ID is rejected as a conflict. The adapter preserves the entire input JSON as a private payload. Strings inside tool results never become user events. Subagent fields cause a gap, not a user event. Stop records a reply but cannot override host stop, plan, or permission controls. Task identity is supplied externally, not inferred from turn_id. Claude prompt IDs identify prompt submissions; a valid UUID supports idempotent replay, while changed content conflicts. Missing prompt IDs, Codex prompt deliveries, Stop and lifecycle events use random IDs to avoid collapsing distinct deliveries; an explicit gap records identity uncertainty. Claude prompt_id identifies the current user prompt, not a Stop invocation: a single prompt can trigger multiple Stop hooks during continuation. SessionEnd can recur across session resume; neither prompt_id nor session_id establishes a unique end invocation. Stop and SessionEnd use distinct fixed gap reasons (`stop_invocation_identity_unavailable` and `session_end_invocation_identity_unavailable`). Identical deliveries cannot be distinguished from separate identical invocations, so both remain separate and both receive gaps; changed payloads are not identity-conflict checked for these events. Codex turn IDs are retained for correlation without assuming unique prompt-delivery semantics.

The 1 MiB input bound protects process memory. Invalid or oversized inputs create a fixed-reason gap for the configured session where possible; malformed or oversized input cannot be attributed to any actual session, so this is an unattributed transport gap rather than proof that the target session lost an event. Unrecognized schema, absent tool IDs, missing fields and subagent scope fail closed. Gaps are recorded before no-ID events to avoid silently appearing complete after an interruption; these are separate SQLite transactions. Storage failure can prevent even the gap from being recorded, so ingestion acknowledgement and coverage are not guaranteed. No transcript files are read, no data is uploaded, and arbitrary errors are not returned to the host.
