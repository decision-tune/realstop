# Local artifact observations

`artifact_checks.check(root, criterion, environment_id, max_bytes=...)` performs a read-only SHA-256 observation for a `CriterionDeclaration`. It returns an immutable observation with a random ID, criterion, host-supplied environment, timestamp, status (`match`, `mismatch`, `missing`, or `unverifiable`) and actual SHA-256 only on a verified read. It does not execute commands, create policy receipts, assert coverage or permissions, or authorize an action. A mismatch is not proof of task failure beyond this exact byte comparison.

The trusted host must supply an absolute canonical local root without symlink components, a trustworthy current environment identity and an authentic declaration. Caller-constructed declarations are validated again. The criterion binds a relative path, expected SHA-256, check and environment. Each root and relative component is opened with directory-relative descriptors and `O_NOFOLLOW`; platforms without required flags or directory-relative opens fail closed. Only regular files are read; the limit defaults to and cannot exceed 16 MiB. Reads are bounded, file metadata is compared before and after, and the entire path is reopened and checked against the read descriptor. Missing during a recheck, symlinks, nonregular targets, environment mismatch, races, excessive size or unsupported operations do not produce a successful observation.

This is a point-in-time observation only. A file, directory, artifact meaning, environment or authority can change immediately afterward, and descriptor/metadata checks cannot rule out every malicious local filesystem race or filesystem that violates expected semantics. No atomic binding to the Supervisor ledger or external action exists. Before acting, a future trusted integration must recheck currency and authorization at its own action boundary; no live integration or execution is provided here. Remote filesystems and device nodes are outside the supported trust model.
