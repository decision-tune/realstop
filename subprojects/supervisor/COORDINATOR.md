# Advisory coordinator prototype

`coordinate(db, provider, session, task, snapshot, action_id, proposed_action, final_reply, source_events, timeout=30)` resolves application source IDs to event IDs already captured in the exact provider/session/task. It reads a bounded, transactionally consistent local snapshot and abstains on any gap, pending, orphan or ambiguous tool call, over-budget scope, missing captured user event, missing referenced fact source, or stale ledger version. The snapshot version is the decimal string form of the ledger version. The caller supplies the typed snapshot and explicit authority facts; this component does not infer obligations or permissions.

Only a captured `UserPromptSubmit` prompt can become user text. Tool events remain tool text and Stop contributes only its final reply. Every captured user prompt in the task must have a source mapping, even if not cited by a policy fact. All other supported captured tool and assistant records are automatically included under supplemental source IDs when not already mapped, so contradictory outputs cannot disappear merely because the application omitted a receipt. The policy validator permits confirmation citations only to source IDs referenced in the typed snapshot; a verifier that cites a supplemental ID can therefore cause an abstention. Source mappings and ledger input originate at trusted local hooks; they are not cryptographically authenticated. Missing historical events are not magically detected: callers must record a coverage gap for unknown history and supply `supported` coverage only when justified. The current capture adapter marks many native events with identity gaps, so this prototype may abstain on ordinary live sessions. Storage failures may prevent recording a gap. No model call occurs when policy or capture checks fail.

Persisted local claims are folded into the snapshot before review to suppress repeat native calls. A confirmed advisory result is saved by `claim_intervention` only if the ledger version is still current and no conflicting claim exists; the binding is stored as its decision digest. Returns contain a reason, validated metadata if saved, and `claim_saved`. It never blocks, executes or emits a continuation.

**Not ready for live intervention.** The SQLite transaction only checks local ledger version and duplicate claims. It cannot lock the host, verify the final reply's currentness externally, prove the application’s source roles or action description, or validate artifact revisions and external permissions. A real integration must implement and validate those boundaries at its action boundary, together with ingestion acknowledgements and provider coverage. The native verifier receives the supplied local source text; disclosure needs authorization. Tests stub transport and do not call a model.
