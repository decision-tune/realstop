# Native review prototype

`native_review.review(snapshot, action_id, proposed_action, final_reply, sources, provider, timeout=30)` returns a reason and either a policy `Intervention` claim or `None`. It never blocks, continues or executes an action. A trusted application supplies a typed policy snapshot, the one selected declared action and its description, and a mapping of source IDs to `{role, text}` originals. The application is responsible for authenticating source roles and ensuring the supplied description actually describes the declared action; the bridge cannot prove either from text. Every obligation, receipt, action and permission source referenced by the snapshot must be supplied before any native call. All obligation and permission sources must be user sources; receipts retain their supplied roles and originals.

The final reply digest is lowercase SHA-256 of its UTF-8 bytes. A separate SHA-256 binding covers canonical JSON of all snapshot facts, source originals, selected ID, proposed action, final reply and provider. Only the selected action and its permissions are included in the prompt; other snapshot actions are included in the binding but omitted from presented facts. Original source text may itself mention other actions; the prompt instructs the verifier to assess only the selected action. Native output must select `confirm_action`, `legitimate_stop` or `insufficient`, echo the binding and the selected action ID (or null for non-confirmation), and for confirmation cite exact substrings for obligation, authorization, unfinished work, feasibility and the selected action source. Citation membership does not prove semantic entailment. Policy validates all cited IDs and the selected action again after native output. The code rechecks its inputs for mutation before returning a claim; it cannot observe external changes that the caller has not supplied.

A confirmed result includes the binding, selected action ID and validated source IDs as audit metadata; quotations are not returned as metadata.

The caller must atomically recheck the authoritative ledger version, final reply, permissions and relevant artifact revisions, and persist any claim before an intervention. That boundary is not implemented. Caller-created snapshots, full authority/coverage assumptions and source originals are trusted inputs, not verified here. No feature is installed into hooks.

The bridge calls the private `realstop.native_verifier._run` interface and duplicates its Claude Sonnet and Codex gpt-6.1-sol restricted CLI options. This coupling can break if the transport contract changes; tests and live validation are required after changes. It uses its own prompt and schema, without changing the existing verifier globals. Input is limited to 32,000 UTF-8 bytes including prompt; output to 16,384 bytes; timeout must be positive and at most 45 seconds. Tool events, malformed responses, timeouts, recursion and missing evidence abstain. The provider receives the selected source text, so callers must authorize that disclosure. The tool restrictions are not a general sandbox.
